# Backstreet Boys / Sphere / 2026 summer protocol

Frozen before fitting order coefficients, 2026-09-29 UTC. This is a retrospective exploratory study, not a preregistered experiment or a trading backtest.

- 21 user-named exports BB716 through BB829, matched to official summer schedule. Filename is the event identity; CSV has no event ID. Preserve bytes, all original strings, row numbers and SHA256.
- Header explicitly says EDT. Treat all timestamps as fixed UTC-04:00 (including February, when New York civil time is EST); create UTC and America/Los_Angeles timestamps. Main summer windows are after DST begins, so this ambiguity does not affect them. Scheduled start 20:00 Pacific supported by Bandsintown and other listings; exact event Ticketmaster URL unavailable. Assume this common scheduled time for all 21 shows; ±1h sensitivity. This is scheduled start, not actual stage arrival.
- Do not round time. Right-closed lead buckets: (0,12] hours, (12,24], (24,48], (48,96], (96,168], >168; zero/negative is at/after scheduled start.
- Normalize whitespace/case separately from originals. Merge '300 level' and '300 Level'. Qty=0 unknown, never one; price positive/finite. Flag missing zone/row, nonnumeric seat rows, invalid fields, prices above $10,000 and log-price >5 robust MAD within zone/source. Outlier flags do not automatically remove observations. Candidate duplicates retained because no sale_id; dedup sensitivity removes only extra identical rows within a file/event.
- Primary seats: 100 Level with Section 101–110 and numeric integer Row 12–37 (range observed in this export). This is an operational numeric-seat group, not a guarantee of unobstructed/non-VIP seats. Use Section × Row fixed effects as sensitivity; never assume Sphere's 100 Level is same product as MSG's. Separate rows <=22 sensitivity without asserting all such seats are unobstructed.
- Primary comparison: sh only, 7<days-to-start<=14. All shows must have records before window start and after window end. Count every record as one observed record, not unique sale or ticket. Assess all-zone daily presence and max gaps as coverage proxies, not proof of stable monitoring.
- Price model: log(price) ~ show_order/10 + Section + Row + Qty group + lead-day bucket + show weekday. Equal total weight each show. Uncertainty: max of event cluster, observation-week cluster, and two-way variance; t critical using min cluster count minus one. Few weeks means exploratory intervals only.
- Activity model: per-show count of eligible ordinary100 sh records in same 7 days, Poisson mean ~ show_order/10 + weekday. Robust variance max HC1, show-week clustered, overdispersed Poisson; t df show-weeks-1. Also report all-zone counts. Coverage stability unverified.
- Predetermined sensitivity: exact Section×Row; exclude first/last summer show; dedup candidates; remove flagged price extremes; only known Qty; rows<=22; 200–400 reserved seats with zone-specific row controls; announcement cohort; 2026-08-10+ observation marker (new dates); equal 0–7,14–21,21–28 day windows; scheduled start ±1h. Not independent discoveries, no multiple-testing correction.
- Do not regress post counts/likes against prices unless contemporaneous comparable post-age metrics and coverage exist. Public cumulative snapshots, fan selection, different post types, multi-year press totals cannot prove fatigue or incremental predictive power. News published after a sale cannot be used as its historical trading signal.
- A single run cannot identify an independent linear show-order effect while fully absorbing arbitrary observation date, show date and lead time. Report association, not causal audience fatigue. BSB vs Harry is a mechanism comparison, not randomized control or a clean difference-in-differences design.
